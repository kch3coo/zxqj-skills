# Style Rules

This file is the operational reference for `youtube-style`.

## Primary Goal

Help a beginner quickly understand:

- why this topic matters
- what the core idea means
- what to do next

The writing should reduce friction, not perform expertise.

## Structural Rules

Default structure:

1. Start from use, pain point, or scenario.
2. Then give the plain-language definition.
3. Then give one small example.
4. Then unpack the process in a beginner-safe order.
5. Then point out mistakes, confusion, or edge conditions.
6. End with a short wrap-up or next action.

If the user already has a structure, improve it without changing the core meaning unless asked.

## Tone Rules

- Use spoken Chinese, not document Chinese.
- Sound calm, direct, and natural.
- Allow light warmth, but do not sound cute on purpose.
- Prefer clarity over cleverness.
- The draft should sound like a human teacher talking, not performing.

Useful phrasing patterns:

- `你可以先这样理解`
- `先别急着记定义`
- `它本质上就是`
- `这里你先抓住一件事`
- `我们先看一个最简单的例子`
- `这一步如果没搞清楚，后面很容易卡住`

## Beginner Safety Rules

- Assume the audience may not know the term you just used.
- If a new concept is required, explain it immediately in plain language.
- Do not pile three new concepts into one sentence.
- Keep examples simple enough that the viewer can mentally follow them once.
- If there is an easy confusion point, state it and tell the consequence.

## Practicality Rules

- Favor real operating context: browser, webpage, tool interface, product action, file, button, or workflow.
- Prefer showing how and why over praising the tool or trend.
- If code appears, explain what the code is doing before or alongside the code.
- If a process has a common trap, mention it near the step where it matters.

## Rewrite Rules

When rewriting an existing draft:

- preserve meaning first
- improve structure second
- improve spoken feel third
- remove filler throughout

Allowed rewrite changes:

- move the opening to a stronger motivation-first start
- break long written sentences into easier spoken sentences
- replace stiff terminology with plain speech
- add short bridging phrases for listening flow

Do not:

- invent claims the draft did not support
- change the main stance without being asked
- over-polish until the draft loses the author's meaning

## Banned Patterns

- definition dump in the first paragraph when motivation is missing
- long abstract framing with no example
- repeated empty emphasis like `非常非常重要`
- generic AI summary sentences that could fit any topic
- excessive `不是……而是……` contrast frames
- too many stacked rhetorical questions
- one sentence per line unless the user wants teleprompter formatting

## Final Quality Check

A good result should satisfy all of these:

- the viewer knows why to keep watching
- the first concrete example arrives early
- difficult words are translated into normal speech
- the piece sounds spoken when read aloud
- each paragraph advances understanding
- there is no obvious AI template smell
