# Yudao Codegen Workflow

这份文档用于 Yudao / ruoyi-vue-pro 的代码生成场景。  
只有用户明确要求 codegen、代码生成、CRUD scaffold、单表 / 树表 / 主子表生成时，才使用这份流程。

## 1. 触发边界

适合使用 codegen 的场景：

- 单表 CRUD 生成
- 树表 CRUD 生成
- 主子表 CRUD 生成
- 基于 Yudao codegen 模板生成后端和前端文件
- 分析 codegen 配置、模板输出路径、front-type

不适合使用 codegen 的场景：

- 已有业务逻辑的小改动
- 状态锁定、错误码、前后端字段联动
- 权限、菜单、字典的局部调整
- 手写复杂业务流程
- 排查 bug 或数据库约束问题

## 2. 生成前置检查

执行或规划 codegen 前，必须确认：

- 当前仓库是 Yudao / ruoyi-vue-pro 风格项目
- codegen 模板或生成器配置存在
- 目标表结构已明确
- 表名符合当前项目约定
- 表注释能表达业务含义
- 关键字段都有注释
- 主键、逻辑删除、租户、审计字段符合项目约定
- 前端目标工程和输出路径明确

## 3. 单表生成检查

单表生成前确认：

- 表名和业务名
- 主键字段
- 必填字段
- 查询字段
- 列表展示字段
- 表单字段
- 字典 / 枚举字段
- 导入 / 导出需求

## 4. 树表生成检查

树表生成前确认：

- 主键字段
- 父级字段
- 名称字段
- 排序字段
- 是否需要祖级路径或层级字段
- 删除时是否限制有子节点

缺少父级字段、名称字段或排序字段映射时，默认停止。

## 5. 主子表生成检查

主子表生成前确认：

- 主表名
- 子表名
- 主表主键
- 子表关联主表字段
- 明细新增 / 修改 / 删除策略
- 删除主表时是否联动删除明细
- 是否存在状态锁定或下游单据限制

缺少明确关联字段时，默认停止。

## 6. Front Type 判断

判断前端类型时，同时检查：

- codegen 配置里的 front-type
- 模板输出路径
- 当前仓库实际前端工程
- 用户明确要求

如果配置、模板和仓库结构冲突，不要猜，先说明冲突。

## 7. 生成前预览

真正生成或覆盖文件前，默认先列出：

- 将生成的后端 Controller / Service / Mapper / DO / VO / Convert
- 将生成的前端 API / 页面 / 表单 / 明细组件
- 将涉及的 SQL / 菜单 / 字典 / 权限
- 是否会覆盖已有文件
- 哪些文件是新增，哪些文件是覆盖

如果会覆盖已有手写代码，必须停止并等待用户确认。

## 8. Hard Stop

遇到以下情况必须停止：

- 任务是否属于 codegen 不明确
- 表结构不完整
- 表注释缺失
- 关键字段注释缺失
- 树表字段映射缺失
- 主子表关联字段缺失
- front-type 或输出路径冲突
- 即将覆盖现有手写文件但未得到明确确认

### Hard Stop 输出边界

遇到 Hard Stop 时，输出只保留三类信息：

- 停止原因：哪一项条件不满足
- 缺失信息：需要用户或代码继续确认什么
- 下一步建议：确认后才能继续生成、预览或修改

不要把 Hard Stop 写成排查日志、长篇推理、责任归因或“为什么不生成”的过程复盘。  
如果用户明确要求分析原因，再单独输出“原因分析”章节。

## 9. 输出建议

如果用户只是要方案，默认输出：

- 场景判断：单表 / 树表 / 主子表
- 前置条件检查结果
- 待确认项
- 预计生成文件清单
- 风险与 Hard Stop 点

如果用户明确要求执行生成，再进入实际生成步骤。

## 10. Codegen 输出净化规则

输出 codegen 方案、预览或停止说明前，默认做一次净化：

- 保留生成类型、目标表、输出文件、覆盖风险和待确认项
- 删除中间猜测、排查过程和模板搜索过程
- 不复制大段生成模板或现有代码
- 不把“为什么不是 codegen 场景”写成长篇说明，除非用户明确要求
