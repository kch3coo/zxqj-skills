# Yudao 方案模板

当任务目标是“先分析代码，再出方案”时，默认按这份模板输出。  
如果信息还没查全，直接写“待确认”，不要省略。

## 模板

```md
# <需求标题>

## 1. 需求理解
- 一句话说明要解决的问题
- 点出是行为调整、字段调整、SQL 调整、状态约束，还是组合修改

## 2. 归属模块
- 仓库层：`backend / frontend / uniapp / simulator / hardware`
- 模块层：例如 `system / infra / bpm / report / member / custom-business-module`
- 页面或接口入口：写出已确认的入口文件 / 类

## 3. 当前链路
- SQL / 表结构入口
- 后端入口：`Controller -> Service -> Mapper / DAL -> DO / VO`
- 前端入口：`api -> views -> components`
- 移动端入口：如涉及移动端，再写页面和接口入口
- 相似实现参考：至少 1 个

## 4. 影响范围
- 后端会改哪些类
- 前端会改哪些页面 / 组件 / API
- SQL 会改哪些主脚本
- 是否涉及菜单、权限、字典、导出、测试数据

## 5. 计划改动点
- 后端：写清要改哪个类 / 方法、加什么校验或调整什么逻辑
- 前端：写清要改哪个页面 / 组件 / API、调整什么交互或校验
- SQL：写清改哪个脚本、改表结构 / 初始化 / 菜单中的哪一类内容
- 其他联动：写清是否涉及权限、字典、导出、流程、移动端或设备侧

## 6. 风险与边界
- 是否涉及主子表
- 是否涉及状态锁定
- 是否涉及下游单据 / 子任务 / 审批 / 设备同步
- 是否涉及 upgrade
- 哪些点仍待确认

## 7. 验证方式
- 轻量验证：
- 如不做高成本验证，明确说明原因
```

## 方案写法约束

当输出目标是“方案”而不是“直接实现”时，默认遵守：

- 方案里的“计划改动点”写落点和逻辑，不写完整实现
- 默认不要直接贴完整 Java 方法、完整 Vue 组件、完整 SQL
- 默认不要把仓库现有代码复制一大段放进方案
- 如需示意，优先使用一句话逻辑描述或 3 到 5 行短伪代码
- 正式方案只保留最终设计结论，不保留推理痕迹、反向解释、排除过程或“为什么不采用某方案”的长段说明
- 如果确实需要说明取舍，只放在“风险与边界 / 待确认”里，用 1 到 3 条短句表达，不写成过程复盘

推荐写法：

- “在 `OrderServiceImpl.createOrderDetail` 插入前增加状态校验，依据主表状态判断是否允许新增明细。”
- “前端保持现有错误提示链路，不改接口结构，只接收后端业务错误码。”
- “新增 `xxx_hdr` 主表和 `xxx_detail` 明细表，方案阶段先确认表职责、关键字段、关联字段、状态字段和 SQL 落点。”

不推荐写法：

- 直接把整个方法体贴进方案
- 直接把完整 `ALTER TABLE`、`INSERT` 或整段 Vue 表单代码贴进方案
- 新增表时直接把完整 `CREATE TABLE` 作为方案主体
- 保留“反向解释小节”“排除理由小节”“过程性说明”“我为什么不这么做”等推理痕迹
- 把方案写成排查日志、思考记录或设计过程复盘

## 正式方案净化规则

输出正式设计文档前，默认做一次净化：

- 删除“反向解释”“排除理由”“过程说明”“为什么不绑定 / 为什么不采用”等小节
- 删除用于推导结论的中间判断，只保留最终结构、字段、查询方式、Service 校验和联动范围
- 删除“我看到 / 我推测 / 我认为 / 这里说明一下”等对话式表达
- 保留必要的业务边界，但改写成最终约束，例如“采购订单明细解绑后不再参与附件查询”
- 如果用户明确要求保留设计取舍、备选方案或 ADR，再单独输出“设计取舍”章节

## 新增数据表方案补充

如果当前方案涉及新增数据表，默认写这些设计要点：

- 表名和表职责
- 是否为主表 / 明细表
- 主从关系和关联字段
- 关键业务字段
- 状态字段
- 审计字段
- 索引 / 唯一约束建议
- 落到哪个 SQL 脚本
- 是否联动初始化数据、菜单 SQL、测试数据

默认不要直接把完整建表 SQL 放进方案。  
只有用户明确要求“给完整建表语句”或“输出表设计 SQL 草稿”时，才展开完整 `CREATE TABLE`。

## 简版模板

如果需求较小，或只需要先快速对齐方案，可以用这个简版：

```md
# <需求标题>

## 1. 需求理解
- 一句话说明要解决什么问题

## 2. 当前链路
- SQL / 后端 / 前端入口各是什么
- 至少一个相似实现参考

## 3. 改动点
- 后端：改哪个类 / 方法，逻辑怎么变
- 前端：改哪个页面 / 组件 / API，交互怎么变
- SQL：改哪个脚本，属于哪类调整

## 4. 风险与边界
- 是否涉及主子表、状态锁定、下游单据、upgrade
- 未确认项写“待确认”

## 5. 验证方式
- 计划做哪些轻量验证
```
