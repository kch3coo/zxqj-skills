# 规则唯一事实源

## 使用约束

本文件是 Yudao 开发工作流的唯一规则事实源。任何“必须、不得、漏项、验收不通过、无法证明”的规则正文，只能在这里维护。

其它文件的职责：

- `SKILL.md` 只保留入口、顺序、硬边界摘要。
- `workflow.md` 只保留开发推进方法。
- `gates.md` 只定义触发条件和规则 ID。
- `frontend-template.md` 只提供实现模板和代码模式。
- `acceptance.md` 只定义验收记录方式。
- `checklists.md` 只提供执行勾选项。
- `templates.md` 只提供输出格式。

修改规则时必须：

1. 先改本文件对应规则 ID。
2. 再检查引用文件是否只引用 ID，没有复制旧正文。
3. 运行 `scripts/check-skill-drift.ps1`。
4. 运行 `quick_validate.py`。

## ARCH-001 规则唯一源和防漂移

定位：防止同一条规则在多个文件内出现不同表述。

必须：

- 规则正文只写在 `references/rule-registry.md`。
- 其它文件只引用规则 ID，并说明触发条件、模板字段或验收记录位置。
- 新增规则必须分配稳定 ID，不能把临时口径散写到模板、清单或门禁里。
- 修改规则必须同步检查 `gates.md`、`acceptance.md`、`checklists.md`、`frontend-template.md`、`templates.md` 是否仍引用正确 ID。
- 每次重构或改规则后必须运行 `scripts/check-skill-drift.ps1`。

不得：

- 不得在 `gates.md`、`acceptance.md`、`checklists.md`、`templates.md` 重新定义一份规则正文。
- 不得把输出模板里的字段写成新的规则。
- 不得保留与本文件冲突的旧口径。

漂移判定：

- 同一规则在两个文件内出现不同“必须/不得/漏项”正文。
- 输出模板包含已经废弃的实现选项。
- 门禁和验收对同一规则给出不同通过条件。
- 技能入口摘要说必须，但引用文件说可选。

## CORE-001 真实证据优先

必须：

- 先读当前项目源码、SQL、配置、运行输出和实际差异，再写方案或修改代码。
- 证据冲突时，优先级为：用户当前轮明确要求、真实项目文件、命令结果、项目内已有文档、通用经验。
- 经验推断只能作为线索，不能作为完成证据。

不得：

- 不得把历史文档、记忆、猜测或相似项目经验写成当前项目事实。
- 不得只看一个页面或一个接口名就确认完整链路。

无法证明：

- 找不到源码、SQL、配置或命令证据时，必须写入无法证明。

## CORE-002 最小切片

必须：

- 一个切片只服务一个明确业务结果。
- 当前切片必须说明入口、数据、动作、结果、允许文件、禁止范围、最小证明。
- 相邻问题、同类页面、同类接口和顺手优化只报告，不自动纳入本轮。

不得：

- 不得默认批量处理同类页面。
- 不得为了顺手清理扩大文件差异。

停止条件：

- 切片不清、证据不足、风险超过授权范围时停止说明。

## CORE-003 复用优先

必须：

- 新增接口、查询、页面动作、字段、字典、导入导出能力前，先查已有 Controller、Service、Mapper、前端 API、组件、枚举、字典和 SQL。
- 已有 API 满足数据、分页、筛选、排序时优先复用。
- 只缺响应字段时，优先扩展数据拥有方响应契约。
- 只缺筛选条件时，优先扩展数据拥有方查询契约。

不得：

- 不得无理由新增重复接口、重复工具方法、重复查询。
- 不得用 `mode`、`viewMode`、`pageType` 等模式参数让一个接口承担不同业务对象。

## CORE-004 执行清单

必须：

- 非平凡开发、修复或跨文件改动前写执行清单。
- 执行清单包含：目标、当前切片、请求范围、允许修改面、禁止修改面、允许文件、禁止文件、测试文件边界、触发规则 ID、允许验证、禁止验证、停止条件、无法证明。
- 没有当前切片、允许范围、测试文件边界或验证边界时，不开始编辑业务代码。

## CORE-005 验证真实性

必须：

- “已验证”只对应实际执行且有结果的验证。
- 未执行的验证写入未验证或无法证明。
- 生产 Java 改动没有编译证据时，不得声称编译通过。
- 默认可执行静态检查、差异检查、引用扫描；构建、编译、开发服务器、浏览器运行验证需要用户当前轮明确授权。

不得：

- 不得把静态阅读、建议、推断、旧记录写成已完成或已验证。

## CORE-006 用户改动和越界边界

必须：

- 保留用户已有改动。
- 发现越界文件或非本轮相关改动时，先报告，不自行恢复。
- 越界恢复、删除、重置、清理必须等用户明确批准。

不得：

- 不得自行回滚用户改动。
- 不得使用未授权的破坏性命令。

## CONTRACT-001 前后端契约一致

必须核对：

- API 路径、HTTP 方法、请求字段、响应字段、必填、默认值。
- 分页、排序、筛选字段。
- 字典、枚举、状态值。
- 权限标识和菜单配置。
- 错误码和异常提示。
- 导入导出字段、文件名、查询条件。
- 金额、数量、日期、布尔、ID 的类型和精度。

验收不通过：

- 页面字段和接口字段不一致。
- 查询条件和后端参数不一致。
- 表单保存对象和后端对象不一致。
- 契约变化没有说明影响面。

## BACKEND-001 后端分层和业务规则

必须：

- Controller 只做入口、权限、参数和响应组织。
- Service 承担业务校验、状态流转、事务边界、主子表同步、幂等、并发和下游影响。
- Mapper 负责清晰 CRUD、条件查询、分页查询和轻量 join。
- 关键业务规则必须能通过 API 或 Service 约束。

不得：

- 不得让 Controller 直接访问 Mapper。
- 不得把关键业务规则只放在前端显隐、按钮禁用或页面提示里。
- 不得把技术错误、类名、SQL 或内部字段直接展示给用户。

## FE-PAGE-001 前端页面固定结构

适用范围：后台管理端 Vue 页面、标准列表页、弹窗选择表、明细表、主子表表格和业务数据表格。

必须：

- 标准列表页包含查询区、列表区、分页区。
- 查询条件和后端分页查询参数一致。
- 表格字段和后端响应字段一致。
- 表单字段和后端保存对象一致。
- 权限按钮使用项目权限指令。
- 弹窗提交成功后刷新列表或更新当前数据。
- 涉及业务数据表格时，同时触发 `FE-TABLE-001`、`FE-ACTION-001`、`FE-COLUMN-001`。
- 涉及业务时间时，同时触发 `FE-TZ-001`。
- 新增或修改前端页面时，同时触发 `FE-MOBILE-001`。

## FE-TABLE-001 表格可拖动框线

必须：

- 所有业务数据 `el-table` 写 `border`。
- 普通业务数据列允许拖动列宽。
- 普通业务数据列不得写 `:resizable="false"`。
- 操作列必须写 `:resizable="false"`。
- 选择列、展开列、序号列、纯图标列、固定窄列可以禁用拖动。
- 主列表、弹窗选择表、明细表、子表、展开行表格、只读业务表格同样执行。

验收不通过：

- 缺少 `border`。
- 普通业务列禁用拖动。
- 操作列未禁用拖动。

## FE-ACTION-001 操作列完整可点击

必须：

- 所有操作列写 `:resizable="false"`。
- 操作列有足够 `width` 或 `min-width`，覆盖按钮文案、图标、间距和权限按钮组合。
- 操作列作为表格最后一列参与正常横向滚动，不得覆盖、挤占或遮挡业务列。
- 表格字段较多时，由表格容器横向滚动承载宽度；用户横向滚动到最后一列后，操作按钮必须完整可见、完整可点。
- 存在操作列时，不得在 `el-table` 上全局开启会影响操作列的 `show-overflow-tooltip`。
- 操作列单元格和父容器不得使用会裁剪按钮的省略号、`overflow: hidden`、强制单行或固定窄宽。
- 操作按钮必须直接可见、直接可点击。
- 按钮多、文案长或权限组合变化时，必须使用加宽操作列、换行、分组直接展示或移动端动作区。
- 操作列不得被列显示隐藏；主表列显示配置中必须锁定不可隐藏。
- 弹窗选择表、明细表、子表、展开行表格只要存在操作列，同样执行。

不得：

- 不得固定操作列右侧。
- 不得在操作列使用 `fixed="right"`、`:fixed="'right'"`、`:fixed="right"` 或项目等价写法。
- 不得用固定操作列解决按钮裁剪问题。
- 不得使用“更多”下拉隐藏操作按钮。
- 不得让用户必须展开下拉才可执行业务操作。

验收不通过：

- 操作按钮被截断、遮挡、裁剪、换到不可见区域、点不到。
- 操作列固定右侧，导致业务列被覆盖、挤出可视区或手机端只剩操作列。
- 操作按钮被放入“更多”下拉或必须展开下拉才可操作。
- 权限变化后按钮组合存在点不到风险。

## FE-COLUMN-001 列显示操作

必须：

- 每个页面只给主表或主列表提供“列显示”操作。
- 查询区或列表工具栏有文案为“列显示”的按钮。
- “列显示”打开复选框弹出层。
- 主表所有业务数据列进入 `toggleableColumns` 或项目等价列配置。
- 主表所有业务数据列使用 `colVisible('字段key')` 或项目等价函数控制显隐。
- 除操作列外，主表业务数据列都必须允许用户隐藏。
- `id` 列进入列显示配置，默认隐藏，用户需要时可以手动打开。
- 操作列固定可见、不可隐藏；如果进入列显示弹层，复选框必须锁定禁用且保持选中。
- 操作列固定可见不是 `fixed="right"`，不得把本规则解释为右侧固定列。
- 选择列、展开列、序号列等功能列不作为普通业务列；由业务状态、选择模式或展开模式控制，不要求进入列显示配置。
- 展开表、明细表、子表、弹窗选择表、表单内编辑表、嵌套表默认不加列显示；用户明确要求时才按单独切片处理。
- 显隐选择使用页面唯一、主表唯一的持久化 key。
- 本地缓存过滤已删除列，并让新增业务列按规则默认可见；`id` 新增或恢复时仍默认隐藏。

验收不通过：

- 缺“列显示”按钮。
- 只有按钮没有复选框。
- 主表业务列未纳入配置或未接显隐控制。
- 非操作列被锁定不可隐藏。
- `id` 默认可见。
- 操作列被隐藏，或因“固定显示”被实现成右侧固定列。
- 缓存 key 不唯一。
- 把列显示误加到展开表、明细表、子表、弹窗表、表单内编辑表或嵌套表，造成规则越界。

## FE-FK-001 外表 ID 可搜索分页下拉

适用范围：查询区、筛选项、表单字段或弹窗选择条件中涉及其它业务表主键的 `xxxId`、`xxxIds` 或项目等价字段。

必须：

- 涉及其它表 ID 的用户可见查询或选择项，默认使用下拉筛选框或项目已有业务选择组件。
- 下拉必须支持输入搜索，优先使用 `filterable`、`remote`、`clearable` 或项目等价能力。
- 远程候选分页默认请求 `pageNo: 1`，`pageSize` 不得低于 20。
- 现有默认候选分页小于 20 时，必须提升到 20。
- 业务为了候选完整性、上下文预加载、批量匹配或性能已评估后主动设置大于 20 时，不得为了本规则强行改小到 20。
- `pageSize: -1`、全部加载或项目等价全量语义不按“小于 20”判定；必须确认它是业务主动全量需求，不是随手绕过分页。
- 下拉提交值可以是 ID，但用户界面的 `label` 不得显示裸 ID。
- 下拉 `label` 必须显示业务可读字段，例如名称、编号、单号、编码，或 `编号 - 名称`、`单号 - 名称` 等组合字段。
- 回显已选值时必须补齐名称、编号、单号或编码；不能因默认分页未包含该 ID 就显示裸 ID。
- 优先复用已有业务选择组件；没有现成组件时，只做当前切片需要的最小封装。
- 表格展示外表关系时，默认展示业务名称、编号、单号或编码；裸 ID 只允许作为默认隐藏列或用户明确要求的调试列。

不得：

- 不得让用户在普通输入框里输入外表 ID。
- 不得把 ID 作为下拉主要展示文本。
- 不得因为接口只返回 ID 就交付显示裸 ID 的下拉；必须换用可返回业务字段的接口或补充返回字段。
- 不得为通用下拉引入复杂白名单、全局映射或超出当前切片的抽象。

验收不通过：

- 查询区或表单暴露其它表 ID 普通输入框。
- 分页下拉默认 `pageSize` 为 1 到 19 且无业务理由。
- 业务主动大于 20 或全量加载的候选分页被强行改小到 20，导致候选不完整或原有操作退化。
- 下拉选项、已选回显或表格关系列显示裸 ID。
- 下拉不能输入搜索。
- 回显缺业务名称、编号、单号或编码。

## SORT-001 金额和时间列排序

适用范围：后台列表页、弹窗选择表、明细表、子表、展开行表格中展示金额字段或时间字段的业务数据表格。

必须：

- 凡是展示金额或时间字段的业务表格列，必须支持排序。
- 金额字段包括单价、金额、总额、税额、含税/不含税金额、货值、成本、应收、应付等项目内等价字段。
- 时间字段包括创建时间、更新时间、业务日期、订货日期、交货日期、发货日期、生产日期、过期日期、事件时间等项目内等价字段。
- 前端表格使用项目公共排序写法：金额和时间列写 `sortable="custom"`，表格监听 `@sort-change`，通过公共 `buildSortingField` 生成 `queryParams.sortingFields`。
- 前端列 `prop` 必须对应后端 DO 的 camelCase 字段名，由系统底层转换为下划线数据库列名。
- 清空排序或重置查询时，必须清空 `queryParams.sortingFields`；存在表格引用时同步调用 `clearSort()` 或项目等价方法。
- 后端分页请求对象需要接收排序字段；非 join 分页优先让 PageReqVO 继承 `SortablePageParam`。
- 非 join Mapper 走系统底层排序能力，保持 `selectPage(reqVO, wrapper)` 或项目等价写法，不新增白名单、不手写排序分发、不重复实现系统已有排序。
- join Mapper 不能只调用默认 `selectJoinPage(reqVO, ...)` 期待自动排序；必须按销售模块等价写法，用 `MyBatisUtils.buildPage(reqVO, reqVO.getSortingFields())` 创建分页对象，再调用 `selectJoinPage(page, DO.class, wrapper)`。
- join Mapper 有默认排序时，只在 `sortingFields` 为空时追加默认排序；前端传入排序后以用户排序为准。
- 排序改动必须核对前端列 `prop`、PageReqVO、Mapper 分页路径和接口请求参数一致。

不得：

- 不得为非 join 场景新增白名单排序、字段分发方法或额外抽象来替代系统底层能力。
- 不得把金额或时间列只做展示、不接排序契约。
- 不得让前端发送展示字段、拼接字段、中文字段名或非 DO 字段名作为 `field`。
- 不得在 join 场景只改前端，不处理后端分页对象接收排序字段和 join 分页排序路径。
- 不得因为默认排序存在，就省略金额或时间列的用户排序能力。

验收不通过：

- 任一金额或时间列没有 `sortable="custom"` 或等价排序入口。
- 前端排序没有发送 `sortingFields`，或字段名和后端 DO 字段不一致。
- 重置查询后页面仍保留旧排序参数或表格排序状态。
- 非 join 页面没有走 `SortablePageParam + selectPage(reqVO, wrapper)` 或项目等价系统排序路径。
- join 页面没有按销售模块等价写法传入 `sortingFields` 构建分页对象。
- 只验证默认排序，不验证用户点击升序、降序、取消排序。

## FE-TZ-001 前端北京时间固定

必须：

- 前端业务时区唯一值是 `Asia/Shanghai`。
- 所有业务时间展示、解析、筛选、默认值、输入、回显、提交、比较、排序、状态判断和过期判断，走公共北京时间工具。
- 无时区业务字符串按北京时间墙上时间解释。
- 时间戳展示时转北京时间。
- 日期字段按北京时间日期处理，不能因设备时区跨日。
- `DatePicker`、`TimePicker`、日期范围选择器做入口和出口成对桥接。
- “今天、本周、本月、最近 N 天”、日初、日末、默认当前时间由北京时间工具生成。
- 第三方日期组件不改源码时，业务入口传北京时间值，业务出口统一按北京时间归一。

不得：

- 不得做成用户可选、环境变量可配、租户可配、项目可配。
- 不得跟随浏览器、电脑、小程序或手机系统本地时区。
- 不得在业务时间字段上直接使用本地 `Date`、`Date.parse`、普通 `dayjs`、本地 `startOf('day')`、本地 `endOf('day')`。
- 不得认为只设置 `format`、`value-format` 已解决时区问题。

验收不通过：

- 业务时间没有固定 `Asia/Shanghai`。
- DatePicker 只设置格式不做桥接。
- 日期字段可能跨日。
- 非北京时间设备时区下展示、筛选、保存再编辑、排序或状态判断偏移。

## FE-DATE-001 时间选择器移动端兼容

必须：

- `DatePicker`、`TimePicker`、日期范围选择器弹层在手机视口内完整可用。
- 开始日期、结束日期、确认、取消、清空、月份切换都能点击。
- Element Plus 的 `daterange` / `datetimerange` 在手机端不得直接交付默认双面板弹层。
- 日期范围控件必须优先复用项目统一响应式日期范围组件；项目没有时，先封装通用组件，再接入业务页面。
- 响应式日期范围组件必须对外保持单一范围值 `v-model` 或项目等价契约，业务页面不得散落维护 `mobileStart`、`mobileEnd`、同步函数等临时状态。
- 响应式日期范围组件桌面端可以继续使用 Element Plus `daterange` / `datetimerange`；手机端必须使用底部抽屉、全屏或单列弹层承载选择流程。
- 响应式日期范围组件必须保持桌面端原有布局契约；替换已有 `el-date-picker` 时，先复用原控件宽度、class、style 和查询区位置，不得无证据放大宽度或改变按钮排列节奏。
- 响应式日期范围组件如增加外层 wrapper，必须把外部 `class`、`style` 和透传属性作用到桌面端真实日期控件，或保证 wrapper 与真实控件同宽；不得让 wrapper 吃掉宽度类导致桌面查询区排版漂移。
- 查询区日期范围控件与搜索、重置、新增、导出、列显示等按钮不得重叠、遮挡、压住、顶到下一层或改变原有可接受间距；空间不足时按钮区换行，日期控件不得侵入按钮区。
- 日期范围宽度调整必须以当前页面原始视觉和实际浏览器测量为依据；只允许使用能解决问题的最小宽度变化，不得默认把查询区范围控件放大为导出弹窗宽度。
- 手机端日期范围选择必须有明确状态机：先选开始日期，再选结束日期；结束早于开始时必须交换或给出明确处理。
- 手机端日期范围选择必须提供清空、取消、确认、月份切换；选择完成后输入框或触发入口必须回显完整范围。
- 日期范围输出必须执行 `FE-TZ-001`，按北京时间生成开始日 `00:00:00` 和结束日 `23:59:59`，或按业务要求输出北京时间日期格式。
- 日期范围在手机端不得只用两个仍会弹出桌面 Popper 的 `el-date-picker type="date"` 作为完整解决方案，除非已在 `375px` 宽度证明弹层、确认、清空和月份切换完整可用。
- 非范围日期在手机端必须使用全屏、抽屉、单列弹层或已验证可用的移动端控件。
- 继续使用桌面日期范围弹层时，必须在 `375px` 宽度证明所有关键操作可见可点。

验收不通过：

- 手机端日期弹层超出视口。
- 第二个月份、确认、取消或清空不可达。
- 日期范围在业务页面复制临时开始/结束状态和同步逻辑，没有统一组件契约。
- 封装后桌面端日期范围宽度、间距、按钮排列相对原页面明显漂移。
- 外层 wrapper 吃掉 `class` 或 `style`，导致真实日期控件宽度不是页面声明宽度。
- 日期范围控件与查询按钮重叠、遮挡、压住、顶到下一层或造成按钮不可点。
- 手机端日期范围选择后未按北京时间归一，或开始/结束日边界错误。
- 未按 `375px` 验证却声称可用。

## FE-MOBILE-001 手机端可用性

必须：

- 所有前端页面在手机端可完成核心业务流程。
- 最小按 `375px` 宽度验收，常规按 `390px` 到 `430px` 复核。
- 搜索区在手机端单列或折叠展示。
- 输入框、下拉框、日期范围、搜索、重置、新增、导入、导出、列显示按钮可见可点。
- 表格允许容器内部横向滚动，但页面主体、搜索区、工具栏、分页、弹窗不得失控。
- 手机端表格保留核心字段可读；字段过多时使用横向滚动、卡片式列表或详情入口。
- 操作列或移动端动作区完整可见、可点击；操作列不得固定右侧遮挡业务列。
- 新增、编辑、详情弹窗接近全宽，弹窗体可滚动，底部按钮可到达。
- 弹窗内表单、Tabs、明细表、添加明细、删除明细、保存、取消可操作。
- 顶部导航、租户选择、标签页、右侧设置按钮、浮动按钮不得覆盖业务内容或拦截弹窗操作。
- 时间选择器同时执行 `FE-DATE-001`。

验收不通过：

- 手机端搜索、时间选择、弹窗、表单、表格或按钮不可用。
- 弹窗底部按钮不可达。
- 只验证桌面，不验证 `375px` 手机宽度。

## QUALITY-001 质量红线

不得引入：

- 查询在循环中触发 N+1。
- 前端循环调用 API。
- MyBatis 列表或导出路径使用 nested select 造成 N+1。
- Controller 直接访问 Mapper。
- SQL 字符串拼接。
- 空 catch 或吞掉业务失败。
- 宽泛捕获后只返回技术错误。
- 硬编码密钥、令牌或真实凭据。
- 技术错误、业务码或内部字段直接展示给用户。
- 业务状态、原因、类型、分组、编码使用魔法值且没有枚举、字典或策略拥有方。
- 关键业务规则只存在于 Vue/TS 页面。
- 无理由新增重复接口、重复工具方法或重复查询。
- 无关格式化、命名调整、抽象重构扩大差异。
- 业务数据表格缺少 `border` 或普通业务列禁用拖动。
- 操作列按钮被截断、遮挡、裁剪、被放入“更多”下拉、必须展开下拉才可操作，或存在点不到风险。
- 操作列固定右侧，导致业务列被覆盖、挤出可视区或手机端只剩操作列。
- 主表缺少“列显示”操作，主表业务列未纳入显隐控制，或 `id` 默认可见。
- 外表 ID 查询或选择暴露普通 ID 输入框，分页下拉显示裸 ID，或默认候选分页小于 20 且无业务全量理由。
- 业务数据表格中的金额列或时间列缺少排序，非 join 没有复用系统底层排序，或 join 没有按销售模块等价写法接入 `sortingFields`。
- 前端业务时间没有写死北京时间 `Asia/Shanghai`，或依赖设备本地时区、可配置时区。
- 日期范围选择器没有复用或封装统一响应式组件，手机端仍交付 Element Plus 默认双面板范围弹层，或页面散落临时开始/结束状态同步逻辑。
- 时间选择器封装后破坏桌面查询区原有宽度、间距、按钮排列，或出现控件与按钮重叠、遮挡、压住。
- 手机端搜索、时间选择、弹窗、表单、表格或按钮不可用。

允许例外必须写明理由、范围和无法证明。

## ERROR-001 错误码

新增业务错误码前必须：

1. 搜索是否已有相同或相近语义错误码；已有则优先复用。
2. 必须新增时，扫描后端所有 `new ReturnCode(...)` 或项目等价写法。
3. 在目标业务编号段选择未使用编号。
4. 新增后再次扫描，确认没有重复。

可使用 `scripts/scan-return-codes.ps1` 做只读扫描。脚本只报告结果，不自动修改代码。

## JAVA-001 Java 编译证据

修改 `src/main/java/**` 下生产 Java 文件后：

- 没有成功编译证据时，不声称编译通过、修复完成或可上线。
- `git diff --check`、静态搜索、前端检查不能证明 Java 编译通过。
- Maven 依赖解析失败且未进入源码编译时，不算 Java 编译证据。
- 未获得用户授权编译时，最终回复写入“未执行编译，无法证明 Java 编译通过”。

## CODEGEN-001 代码生成边界

只有用户明确提到代码生成、CRUD scaffold、单表、树表、主子表或模板生成时，才按 Codegen 思路处理。

进入 Codegen 前必须确认：

- 生成类型。
- 表结构、表注释、关键字段注释。
- 模板或生成器配置。
- 前端类型和输出路径。
- 是否会覆盖已有手写代码。

信息缺失、路径冲突或可能覆盖手写代码时，停止并列出待确认项。
