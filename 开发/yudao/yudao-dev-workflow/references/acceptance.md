# 验收规则

## 定位

本文件只定义“如何记录验收”。规则正文、漏项和验收不通过条件以 `references/rule-registry.md` 为唯一来源。

验收不是建议。触发的规则 ID 必须有结论：通过、未通过、未验证、无法证明、用户明确暂缓。

本文件只回答两个问题：

- 要记录哪些证据。
- 最终回复如何区分通过、未通过、未验证和无法证明。

本文件不回答“规则本身是什么”。判断是否通过时，必须回到 `references/rule-registry.md` 对应规则 ID。

## 验收流程

1. 从执行清单读取触发规则 ID。
2. 到 `references/rule-registry.md` 读取每个规则 ID 的必须、不得、验收不通过和无法证明。
3. 对每个触发规则给出证据。
4. 证据不足时写未验证或无法证明，不得写通过。
5. 有未通过项时，先修复；用户要求暂不修复时，最终回复写明残余风险。

## 验收记录模板

```text
验收记录：
- 当前切片：
- 触发规则 ID：
- 已通过：
- 未通过：
- 未验证：
- 无法证明：
- 用户明确暂缓：
- 残余风险：
```

## 前端验收组合

前端页面验收按规则 ID 记录。下表只用于快速列出常见触发组合，具体规则正文仍以 `references/rule-registry.md` 为准：

| 场景 | 必查规则 ID |
| --- | --- |
| 任意新增或修改前端页面 | `FE-PAGE-001`、`FE-MOBILE-001` |
| 业务数据表格 | `FE-TABLE-001`，有操作列时查 `FE-ACTION-001` |
| 页面主表或主列表列显示 | `FE-COLUMN-001` |
| 外表 ID 查询、筛选、选择或回显 | `FE-FK-001`、`CONTRACT-001` |
| 金额列或时间列排序 | `SORT-001`、`CONTRACT-001` |
| 操作列、行级按钮、权限按钮 | `FE-ACTION-001`、`PERM-001`、`UX-001` |
| 业务时间、日期筛选、默认时间、时间回显 | `FE-TZ-001` |
| 日期、时间、日期范围、时间范围控件 | `FE-DATE-001`、`FE-TZ-001`、`FE-MOBILE-001` |
| 弹窗、表单、保存、取消、详情 | `FE-FORM-001`、`FE-MOBILE-001`、`CONTRACT-001` |

前端验收不得只写“页面已改”。必须说明触发规则 ID 的结论和无法证明范围。

主表列显示证据记录字段：

- 页面主表或主列表是否有“列显示”入口。
- 展开表、明细表、子表、弹窗表、表单内编辑表或嵌套表是否没有被误加列显示。
- 主表所有业务数据列是否纳入显隐控制。
- 除操作列外，主表业务数据列是否都可隐藏。
- `id` 列是否默认隐藏，并可在列显示中手动打开。
- 操作列是否固定可见、不可隐藏，且没有使用右侧固定列。

外表 ID 下拉证据记录字段：

- 涉及其它表 ID 的查询、筛选、表单或弹窗选择条件是否没有使用普通 ID 输入框。
- 下拉是否支持输入搜索。
- 默认远程候选分页是否为 `pageNo: 1` 且 `pageSize` 不低于 20。
- 候选存在多页时，下拉滚动到底是否能继续加载下一页，或是否复用项目已有分页远程下拉组件。
- 是否排除了只查第一页导致后续候选无法选择的情况。
- 当前写法低于 20 时是否提升到 20；当前写法大于 20 或全量加载时是否保留业务意图，未强行改小。
- 下拉选项和已选回显是否显示名称、编号、单号、编码或组合字段。
- 下拉 `value` 是否提交 ID，但用户界面不显示裸 ID。
- 默认分页没有当前 ID 时，是否通过详情或等价接口补齐业务字段回显。

日期范围控件证据记录字段：

- 是否复用或封装统一响应式日期范围组件。
- 桌面端范围选择是否保持原有业务契约。
- 桌面端是否保持原控件宽度、查询区位置和按钮排列；若宽度变化，是否为解决重叠的最小变化。
- 外层 wrapper 和真实日期控件的浏览器实测宽度是否一致，外部 `class`、`style` 是否作用到真实控件。
- 查询区日期控件是否没有与搜索、重置、新增、导出、列显示按钮重叠、遮挡、压住或造成不可点。
- 手机端 `375px` 是否能打开弹层、选择开始日期、选择结束日期、切换月份、清空、取消和确认。
- 输出值是否按 `FE-TZ-001` 归一为北京时间范围。
- 业务页面是否删除临时移动端开始/结束状态同步逻辑。

金额和时间列排序证据记录字段：

- 哪些金额列、时间列触发 `SORT-001`。
- 前端点击升序、降序、取消排序时 `sortingFields` 是否正确变化。
- 列 `prop` 是否对应后端 DO 的 camelCase 字段名。
- 非 join 是否走系统底层 `SortablePageParam + selectPage(reqVO, wrapper)` 排序路径。
- join 是否走销售模块等价的 `MyBatisUtils.buildPage(reqVO, sortingFields) + selectJoinPage(page, ...)` 排序路径。
- 重置查询是否清空 `sortingFields` 和表格排序状态。

## 后端和数据验收组合

| 场景 | 必查规则 ID |
| --- | --- |
| Controller、Service、Mapper、事务、校验 | `BACKEND-001` |
| 前后端字段、接口、分页、筛选、排序 | `CONTRACT-001` |
| 金额列或时间列排序 | `SORT-001`、`CONTRACT-001` |
| SQL、DDL、索引、约束、初始化数据 | `SQL-001` |
| 权限、菜单、按钮、后端权限标识 | `PERM-001` |
| 字典、枚举、状态展示 | `DICT-001` |
| 状态流转、审批、撤销、关闭、锁定 | `FLOW-001` |
| 导入导出、Excel、模板、文件名 | `IMPORT-001` |
| Java 生产代码 | `JAVA-001` |
| 错误码 | `ERROR-001` |

## 验证证据

默认至少核对：

- 差异范围：`git diff` 或等价差异查看。
- 格式和冲突标记：`git diff --check` 或等价检查。
- 引用和契约：`rg` 或源码阅读。
- 触发规则 ID 对应的静态证据。

需要用户当前轮授权后才能声称通过：

- Maven 编译、打包。
- 前端完整构建或完整类型检查。
- 开发服务器。
- 浏览器运行验证。
- 运行时探测。

## 未通过处理

出现以下情况不得说完成：

- 触发规则 ID 没有验收记录。
- 规则要求的证据缺失却写成通过。
- 用户可见行为没有证据且未写无法证明。
- 生产 Java 修改没有编译证据却声称编译通过。
- 手机端、北京时间、列显示、操作列、可拖动框线等前端硬规则缺少结论。
- 外表 ID 查询、分页下拉或回显显示裸 ID，下拉只查第一页无法选择后续候选，或未记录 `FE-FK-001` 结论。
- SQL、权限、字典、状态或契约没有拥有方证据。

如果用户要求暂不修复，最终回复必须写入未验证范围、无法证明和残余风险。
