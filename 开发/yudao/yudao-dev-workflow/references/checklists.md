# 开发检查清单

## 定位

本文件只提供执行检查项。规则正文以 `references/rule-registry.md` 为唯一来源。

使用方式：先在 `references/gates.md` 确定触发规则 ID，再按本清单检查证据。

清单项只用于防漏和取证，不替代规则判定。遇到清单项和 `references/rule-registry.md` 表述不一致时，以规则 ID 正文为准，并按 `ARCH-001` 修正漂移。

## 编辑前

- 已判断任务类型。
- 已读取 `references/rule-registry.md` 中触发规则 ID。
- 开发或修复任务已写执行清单。见 `CORE-004`。
- 当前切片、请求范围、允许修改面、禁止修改面明确。见 `CORE-002`。
- 已确认测试文件边界。见 `TEST-001`。
- 已确认用户已有改动不会被覆盖。见 `CORE-006`。
- 已记录初始无法证明项。见 `CORE-005`。

## 调研

- 已先看真实项目入口。见 `CORE-001`。
- 已按 `SQL -> DO/VO -> Mapper -> Service -> Controller -> 前端 API -> 前端页面` 链路核对。
- 涉及权限、字典、状态流、主子表、导入导出时，不只看一个文件。
- 已查相似实现和项目标准写法。见 `CORE-003`。
- 发现相邻问题时先报告，不自动纳入本轮切片。见 `CORE-002`。

## 实施

- 只修改当前切片的最少文件。见 `CORE-002`。
- 不把业务规则只写在前端。见 `BACKEND-001`。
- 不新增重复接口、重复查询或重复工具。见 `CORE-003`。
- 不创建临时测试文件，除非用户明确要求。见 `TEST-001`。
- 不新增 `version-upgrade` 替代主 DDL，除非用户明确要求。见 `SQL-001`。
- 不保留一次性脚本或临时验证产物。见 `CORE-006`。

## 编辑后

- 实际修改文件都在允许文件或允许修改面内。
- 禁止文件没有被修改。
- 没有把相邻问题、同类页面、同类接口纳入本轮。
- 没有创建或修改未授权测试文件。
- 没有新增无关抽象、清理、重构或依赖。
- 触发规则 ID 有证据，缺失证据已写入无法证明。

## 后端

- `CONTRACT-001`：请求、响应、分页、筛选、排序、错误码一致。
- `SORT-001`：金额列和时间列排序路径正确；非 join 复用系统底层排序，join 按销售模块写法接入 `sortingFields`。
- `BACKEND-001`：Controller、Service、Mapper 分层清楚。
- `PERM-001`：前端权限和后端权限一致。
- `DICT-001`：字典、枚举、状态展示一致。
- `FLOW-001`：状态变更有前置、后置、禁止路径和下游影响。
- `JAVA-001`：生产 Java 修改没有编译证据时，不声称编译通过。

## 前端

- `FE-PAGE-001`：页面结构、查询区、列表区、分页区、弹窗刷新完整。
- `FE-TABLE-001`：业务表格有可拖动框线。
- `FE-ACTION-001`：操作列完整可见、完整可点击，按规则正文核对固定、裁剪、下拉隐藏和移动端动作区。
- `FE-COLUMN-001`：页面主表列显示按规则正文核对主表范围、默认隐藏、可隐藏列、操作列锁定和非主表排除。
- `FE-FK-001`：外表 ID 查询、筛选、选择或回显按规则正文核对搜索、候选分页、滚动到底加载下一页、名称类字段回显和裸 ID 禁止项。
- `SORT-001`：金额列、单价列、总额列、税额列、货值列、日期列和时间列按规则正文核对前端排序参数和后端分页路径。
- `FE-TZ-001`：业务时间固定北京时间 `Asia/Shanghai`。
- `FE-DATE-001`：时间选择器和日期范围按规则正文核对手机端流程、响应式组件、桌面布局保真和北京时间输出。
- `FE-MOBILE-001`：手机端 `375px` 核心流程可用。
- `FE-FORM-001`：弹窗、表单、保存、取消可用。

## SQL、权限、字典、状态

- `SQL-001`：表、字段、索引、约束落到主 DDL 或建表脚本。
- `PERM-001`：菜单、按钮、路由、后端权限标识一致。
- `DICT-001`：字典类型和值、中文显示、历史兼容、未知值兜底一致。
- `FLOW-001`：状态字段、触发动作、并发、撤销、下游影响已说明。
- `IMPORT-001`：导入模板、导出字段、格式、权限和数据范围一致。

## 用户视角

- `UX-001`：操作角色和入口渠道明确。
- `UX-001`：用户任务、可做和不可做边界明确。
- `UX-001`：成功反馈、失败反馈和恢复动作明确。
- `UX-001`：用户可见文案没有技术细节。

## 质量红线

- 已按 `QUALITY-001` 检查 N+1、循环调用、SQL 拼接、空 catch、硬编码密钥、魔法值、重复接口、无关重构。
- 前端页面已按 `FE-*` 规则检查。
- 后端和契约已按 `BACKEND-001`、`CONTRACT-001` 检查。

## 验证

- 已执行允许范围内的静态检查和差异检查。
- 超出执行清单验证范围的命令未自行执行。
- 构建、编译、浏览器验证有当前轮授权才声称通过。
- 没有执行的验证写入无法证明。见 `CORE-005`。

## 验收

- 已按 `references/acceptance.md` 记录触发规则 ID。
- 每个触发规则 ID 都有通过、未通过、未验证或无法证明结论。
- 未通过项已修复，或按用户要求写入残余风险。
- 最终回复区分完成、验证、未验证、无法证明、风险。

## Skill 维护

- 修改规则正文时先改 `references/rule-registry.md`。见 `ARCH-001`。
- 引用文件只引用规则 ID，没有复制旧规则正文。
- 已运行 `scripts/check-skill-drift.ps1`。
- 已运行 `quick_validate.py`。
